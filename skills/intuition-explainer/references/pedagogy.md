# Pedagogy: design a reason to think

The essential unit is a learner question and a manipulable experiment. A graph
without a question is a display. A slider without a consequence is a widget.

## The learning loop

**PREDICT → MANIPULATE → OBSERVE → EXPLAIN → GENERALIZE**

1. Present a comprehensible state and ask for an outcome, construction, or choice.
2. Commit the prediction before showing the answer. Let setup manipulation
   precede commitment when needed to understand the objects.
3. Apply the manipulation and reveal the computed consequence; make the causal
   correspondence visible. Keep the before-state available.
4. Ask for a short explanation, then supply feedback tied to this actual state.
5. Change one assumption or representation and test whether the idea transfers.

Do not require a quiz for every tiny operation. Use the loop where a prediction
reveals the learner's mental model. A wrong answer is useful evidence, not a
failure requiring punishment, confetti, or repeated guessing until “correct.”
Offer a hint or reveal route if a task would otherwise trap the learner.

## Build the need before the name

Start with a mystery; strip it to the smallest concrete world. Allow an early
action, ask for a prediction, reveal a pattern, then let the learner break a
naive rule. Introduce the missing idea and repeat the experiment. Only then
name it, express it formally, and reconnect it to the original problem.

The approximate arc is hook, smallest world, first interaction, prediction,
reveal, counterexample, new idea, formal bridge, generalization, transfer. These
may share a screen or require a detour. The count of stages has no pedagogical
value by itself.

For gradient descent, “move against the slope” is local advice. A large jump
can land higher. The update equation becomes useful when the learner needs a
repeatable rule connecting position, slope, and distance. Printing that equation
on the first screen bypasses the very obstacle the site should help resolve.

## Make misconceptions observable

For each misconception, write two competing predictions and find an input where
they disagree. Implement that input as a reversible experiment. A paragraph
headed “Common misconception” does not substitute for the experience.

Use boundary and limiting cases: a zero vector, tied scores, a disconnected
graph, a degenerate dataset, an empty queue, or a violated theorem assumption.
Explain exceptions instead of silently clamping away the revealing behavior.

## Transfer without imitation

Change a feature that matters: rotate the geometry, change the dataset,
reverse the question, remove an assumption, give an unfamiliar graph, or ask
what experiment a new hypothesis would require. Preserve the underlying idea.
Require a prediction or explanation before revealing. A “next” button and the
same example with new colors do not test transfer.

End by asking for a plain-language explanation, not a vocabulary recital. Map
the toy world's objects back to the real concept and name the remaining gap.
Then leave the model available for free experiments.

## Checks while designing

- What can the learner do in the first minute, before advanced terminology?
- Which observation changes their explanation of what is happening?
- What would someone with the naive model predict differently?
- What can they reason about afterward that they could not reason about before?

If these answers are vague, simplify the target and redesign the experiment
before adding prose or polishing the visual style.
